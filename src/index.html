Bienvenue dans Gastinel Weather Studio

L'application fonctionne sans rien configurer. Une seule fonction demande une clé : l'agent IA, qui commente vos relevés. La clé est gratuite et se crée en deux minutes.

  1. Ouvrez la page des clés d'API de Groq :
  2. Connectez-vous, ou créez un compte si vous n'en avez pas.
  3. Dans le menu, allez à la section API Keys.
  4. Cliquez sur Create API Key pour générer une clé.
  5. Copiez la clé — Groq ne l'affiche qu'une fois — et collez-la ci-dessous.

Vous pourrez la renseigner ou la changer à tout moment dans Paramètres → Agent IA (Groq).

Avant de commencer

    API Infoclimat

    La clé est liée à votre adresse IP publique

    Infoclimat associe chaque clé à l'adresse IP déclarée au moment de sa génération. Si votre box redémarre et que l'opérateur vous attribue une nouvelle IP, les appels échouent — alors que la clé est toujours valide. Il faut alors regénérer une clé sur infoclimat.fr/opendata depuis ce poste, ou activer le relai SSH ci-dessous vers votre serveur à adresse IP stable.

    Relai serveur (SSH) Fait passer les requêtes Infoclimat par votre serveur Debian distant (via curl) pour utiliser son IP fixe ou déclarée. Désactivé par défaut (appels directs depuis ce poste sans relai). Les appels Groq restent directs.
    Connexion explicite : une application desktop ne peut pas « se raccrocher » automatiquement à un terminal SSH déjà ouvert en tâche de fond. Enregistrez ici les paramètres de connexion une fois pour toutes.

Les mesures obtenues sont identiques à celles d'un export .xls — c'est vérifié mesure par mesure par un test permanent. Si ElitechLog est ouvert, fermez-le : un seul logiciel à la fois peut parler au logger.

            Déposez ici un export téléchargé depuis infoclimat.fr/opendata, au format JSON ou CSV — le format est reconnu d'après le contenu du fichier, il n'y a rien à choisir. Les deux portent les mêmes champs et passent par le même lecteur. Aucun réglage d'horloge n'est demandé : le champ dh_utc est de l'UTC vrai, il n'y a ni fuseau à corriger ni ambiguïté jour/mois à trancher.

            Déposez ici un fichier archives_*.csv téléchargé depuis romma.fr. Aucun réglage d'horloge n'est demandé : la colonne timestamp de ces archives est un horodatage Unix en UTC (les colonnes Date et heure, elles, sont en heure locale et ne sont pas utilisées).
            Les fichiers climato_*.csv ne sont pas acceptés : ce sont des moyennes journalières que l'application recalcule elle-même à partir des mesures détaillées.
            Ces archives sont volumineuses (neuf ans d'historique au pas de 10 minutes font environ 40 Mo et 480 000 lignes) : comptez quelques secondes.

            Effacer la mémoire du logger ?

            Cette opération efface les mesures du boîtier physique, et elle est irréversible : le logger ne les contiendra plus.
            Les données déjà importées dans l'application restent intactes — rien n'est supprimé de la base, des statistiques ni des exports.

            Supprimer ce point ?

            Les séries et mesures associées seront également supprimées. Ctrl+Z annule la suppression tant que l'application reste ouverte.

            Ce contenu a déjà été importé

            Rien n'a été enregistré. Forcer l'import n'a de sens que si ces données proviennent réellement d'un autre logger ayant produit, par coïncidence, exactement les mêmes valeurs aux mêmes instants.

            Imports du projet

            Chaque ligne est un import : un fichier de logger, une saisie ou une récupération par API. Anciennes données : première mesure enregistrée. Dernières données : mesure la plus récente. Le dernier appel est le moment où l'API a été interrogée, même si elle n'a rien renvoyé de neuf.
